# Three Amigos

Discovery phase before code. Lisa, Eric, Dude define WHAT before WHO writes it.

## The Problem

Lisa writes scenarios alone and takes the lazy path. Eric only reacts after. The dude ends up doing all the thinking. Three agents arguing before code gets written produces better output than one agent working solo.

## The Session

Dude describes the feature. Lisa and Eric run in parallel — Lisa thinks about edge cases and scenarios, Eric thinks about domain language and boundaries. Dude mediates, synthesizes, decides.

## Output

- Agreed scenario list
- Confirmed terminology (new glossary terms if any)
- Ready for DDD step 1

## What We Learned

- Lisa went cowboy when left alone — deleted CLAUDE.md sections, broke shell escaping, made unauthorized changes. Three Amigos would have caught the scope before she started.
- Eric is good at catching domain drift but only after the fact. Getting him in early means fewer rewrites.
- The knock-knock joke DSL discussion was a natural Three Amigos session — dude proposed, Eric corrected the DSL violations, Lisa drafted. The back-and-forth produced a better scenario than any one of them alone.
- The /reply verb was discovered through this kind of three-way discussion. Eric saw that /abided was overloaded, Lisa showed how it read in scenarios, dude saw the pattern.
